# BiliFlow v3.9.1 Home Feed Regression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent Bilibili iOS 9.6.1 non-empty home responses from becoming an empty feed while continuing to remove explicit ads and non-video cards.

**Architecture:** Keep the endpoint registry, gRPC pipeline, and CDN runtimes unchanged. Replace only the home JSON card predicate with exclusion-first AV evidence helpers, add two bounded fallback levels in `handleFeed()`, and make the existing one-shot refill run only for 1–5 retained videos using canonical video identities.

**Tech Stack:** ES5-compatible JavaScript for Shadowrocket, Node.js built-in test runner, existing deterministic `scripts/build.mjs` release pipeline.

### Task 2: Implement exclusion-first AV recognition and empty-feed fallbacks

**Files:**
- Modify: `src/bilibili-enhance.js`
- Test: `test/bilibili-enhance.test.js`

- [ ] **Step 1: Add home-only evidence helpers**

Implement helpers equivalent to:

```js
function isPlainHomeFeedVideo(item) {
  if (hasExplicitHomeCommercialEvidence(item)) return false;
  if (hasExplicitHomeNonVideoEvidence(item)) return false;
  var explicitAv = hasHomeAvTypeEvidence(item);
  return explicitAv && hasStrongHomeVideoIdentity(item, explicitAv);
}
```

Collect identity from `item`, `player_args`, `playerArgs`, `archive`, `video`, and `basic`. Treat positive aid/avid, strict BVID, positive/BVID param, supported video URI, or player identity as strong; cid remains fallback-only auxiliary evidence. Known card types are positive type evidence, not a whitelist.

- [ ] **Step 2: Add bounded fallback selection in `handleFeed()`**

For non-empty input: normal filter first; if zero, retry with explicit AV plus strong-or-cid identity while still excluding commercial/non-video cards; if still zero, retain up to six source cards excluding only explicit commercial/Banner cards; if still zero, leave the original response unchanged and set diagnostic reason `feed-empty-fail-open`. Empty server arrays remain untouched.

- [ ] **Step 3: Canonicalize refill identities**

Deduplicate aid/avid, BVID, param, and parsed video URI across all reviewed identity containers. Do not use cid alone as a refill identity. Keep the existing one-shot header, timeout, original request URL/identity, and six-item cap.

- [ ] **Step 4: Restrict refill to retained lengths 1–5**

Change the runtime condition from `length >= 0 && length < 6` to `length > 0 && length < 6`, preserving one `$done()` on success, timeout, and failure.

- [ ] **Step 5: Run the focused test and observe GREEN**

Run the same focused Node test and require zero failures.
