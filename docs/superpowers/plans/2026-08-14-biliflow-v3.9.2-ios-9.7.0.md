# BiliFlow v3.9.2 Bilibili iOS 9.7.0 Compatibility Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the four reported Bilibili iOS 9.7.0 commercial UI classes on every fresh response, prevent conditional-cache reinjection after resume, and preserve the existing home fail-open, gRPC wire preservation, and CDN hot paths.

**Evidence boundary:** Latest `origin/main` is still `0e17118131615adfa3549bccbaa544a772182122`. The workspace contains only a Bilibili 9.5.0 PacketTunnel log, not a 9.7.0 capture. Public upstream confirms the existing Search v1, View v1, and ViewUnite v1 fields but does not prove a new 9.7.0 field number or endpoint. Therefore this is a 3.9.2 bounded JSON-structure/cache/diagnostic update; no protobuf number or endpoint will be invented. Exact 9.7.0 capture instructions and unresolved fields will be published separately.

**Architecture:** Keep `src/bilibili-endpoints.js` as the only matcher source and leave CDN hostAuto v10/mediaRoutes v9 untouched. Add endpoint-local, bounded JSON container walkers for Search and View, structural commercial-product detection for relates, precise reason/path diagnostics, and stronger request/response no-cache metadata. Continue using raw-field protobuf transforms for only the already-confirmed fields.

**Tech Stack:** ES5-compatible JavaScript for Shadowrocket, Node.js built-in test runner, JSON fixtures, existing deterministic `scripts/build.mjs` release pipeline.
