## 安装与更新

- [ ] raw 安装链接能够唤起 Shadowrocket 并下载模块。
- [ ] CDN-only、Enhanced 两个固定 URL 均可独立安装。
- [ ] 历史 `Bilibili.CDN.sgmodule` 与 Enhanced 内容和版本一致。
- [ ] 模块信息页显示正确名称和版本。
- [ ] “编辑参数”显示全部参数，中文说明可读。
- [ ] 更新到 3.8.2 后可见 `首页推荐6个普通视频`、`测速方式` 与 `CDN 学习状态`，
      模块脚本 URL 含 `?v=3.8.2`，并包含 `Bilibili Enhance Fresh UI`、
      `Bilibili Story Safe Pipeline` 与唯一一条 `Bilibili CDN Background Benchmark`
      cron（含 `wake-system=1`），以及唯一一条 `Bilibili CDN Cached Media Route`
      请求脚本。
- [ ] `更新模块` 能从同一 raw 地址获取当前版本。
- [ ] 更新后 `[Rule]` 与 `[Script]` 的远程 URL 带当前 `?v=` 版本键，脚本 URL
      页面不再引用上一版本键。
- [ ] 更新后用户设置的策略和开关仍保持预期值。
- [ ] CDN-only 中没有 `Bilibili Enhance` 脚本或 Enhanced 专属 MITM 主机。
- [ ] Enhanced 同时包含 CDN JSON/gRPC 与广告/UI JSON/gRPC 脚本。
- [ ] HTTPS 解密主机只新增 README 列出的 Bilibili API，不含媒体 CDN。
- [ ] CA 描述文件已安装并完全信任；Bilibili 无证书警告。

## BiliFlow 网站

- [ ] iPhone Safari 纵向布局无横向溢出，底部一键安装栏不遮挡最后一项。
- [ ] iPad Safari 纵向/横向布局均可读，双栏摘要与设置顺序合理。
- [ ] CDN-only 与 Enhanced 切换后，只显示该变体适用的选项。
- [ ] 首页、“我的服务”“更多服务”的开关表示“是否显示”，与模块隐藏参数相反映射正确。
- [ ] 关闭“界面逐项精简”后，摘要显示所有可配置入口实际保留，同时此前选择仍被记住。
- [ ] 刷新页面后，本机选择从 `localStorage` 恢复；清除网站数据后恢复仓库默认值。
- [ ] 复制的 `/module.sgmodule?...` URL 能返回 `text/plain` 模块并包含所选参数。
- [ ] 一键安装链接可唤起 Shadowrocket；随后从同一 URL 更新时保留所选参数。
- [ ] 未知参数、重复参数、越界数字、非法 CDN 主机和换行/结构注入返回 `400`。
- [ ] GitHub 最新目录不可用时只使用同一站点部署提交中的已审核目录/模块快照；
      在线与快照来源漂移、目录与模块不匹配或结构校验失败时返回 `502`。
- [ ] 页面无登录、Cookie 横幅、分析请求或第三方用户数据上报。

## 路由

- [ ] Shadowrocket 首页“全局路由”为“配置”时规则生效。
- [ ] 中国大陆 `分流策略=DIRECT`：首页、视频、番剧、评论、弹幕、直播可用。
- [ ] 海外使用真实大陆回国策略：上述流量命中目标策略。
- [ ] 海外无回国策略、使用 `DIRECT`：不把地区版权限制误判为脚本故障。
- [ ] `PCDN策略` 与 `分流策略` 相同时不额外阻断窄 PCDN 域。
- [ ] `PCDN策略=REJECT` 时只观察到 `*pcdn*.biliapi.net` 命中拒绝。
- [ ] 模块没有添加宽泛 IP/CIDR 或 MCDN 全域拒绝。

- [ ] 普通 UGC 视频起播、暂停、续播和拖动进度正常。
- [ ] 短视频、竖屏视频、稍后再看、收藏/历史入口和连续播放均正常使用当前
      PlayerUnite/PlayURL 播放地址，不出现画面撕裂、错误音轨或异常重连。
- [ ] DASH 视频与音频同时正常，无“有画面无声音”或反向情况。
- [ ] 切换清晰度、帧率/编码后仍正常，各表示没有复用错误缓存。
- [ ] 免费 PGC/番剧正常。
- [ ] 账号已合法购买/授权的 PGC/PUGV 内容正常。
- [ ] PGC gateway `v1/v2` 与课程/cheese 播放入口均能解析压缩或未压缩 gRPC，
      无法解析时原始响应仍可播放。
- [ ] DURL/分段视频正常，分段顺序没有变化。
- [ ] 默认 `测速方式=cron` 时，playurl/PlayerUnite 的响应脚本不发起任何 Range
      请求；冷状态立即使用服务端返回的完整 Akamai URL，若没有完整 Akamai URL
      则保持服务端原始地址，绝不只替换为 Akamai 主机名。
- [ ] JSON、gRPC、Story 与 Story gRPC 的热路径均在读取本地状态后立即 `$done()`；
      起播、2 倍速、连续大幅拖动和反复切清晰度时没有由脚本测速造成的等待。
- [ ] 横屏/竖屏、历史/收藏、连续播放以及后台恢复后，App 缓存或预加载的旧 cosov
      地址在同一媒体对象已有 v9 记录时由轻量请求脚本直接命中完整目标 URL；不会先
      等待约 3 秒再回退。
- [ ] v9 目标 URL 保留目标自己的完整签名；原请求的 Range、User-Agent、音视频、
      清晰度和表示档案不变，不会跨 path、`trid` 或签名身份复用。
- [ ] v9 状态最多 64 条，在签名到期前至少 30 秒且最长 2 小时失效；过期、损坏或
      不匹配时原地址放行，下一份新播放响应可重新填充。
- [ ] 点播/直播媒体 CDN 仍不在 MITM 列表中；请求直达不读取媒体响应体。
- [ ] 每个 CDN 模块只有一条后台测速 cron；测速请求使用独立
      `BiliCDN-Background-Benchmark/8` UA 与 `X-BiliCDN-Background: 1`，不会再次
      命中播放响应改写，也不携带 Cookie、SESSDATA、access_key 或当前播放签名 URL。
- [ ] 后台任务先用匿名公共样本解析服务端播放地址，再串行执行 64 KiB 前缀和轮转
      1 MiB 文件内部 Range；单请求硬截止 5 秒，失败时释放锁并保留可播放原地址。
- [ ] Range 起止、总长度、实际长度和样本 hash 全部相同才记为同一对象；出现内容
      压缩、跨对象重定向、HTML/JSON/XML/错误页、200 全量响应或 403 均不晋升。
- [ ] 主机至少通过两个不同媒体对象，最近成功不超过 6 小时，失败率不高于 25%，
      且 p25 吞吐达到 `max(10 Mbps, 当前表示带宽 × 1.8)` 后才可用于热路径。
- [ ] 已选主机一次失败只记账；连续两次失败后立即取消选择并熔断 2 小时，期间不再
      挑战该主机；抖动、失败率或样本新鲜度超限时同样回退冷启动策略。
- [ ] 提升任一线路后，服务端原始主 URL 仍作为第一备用存在；音频、视频、分段、
      表示与清晰度各自只保留自身 path/query，不复用其他对象的签名 URL。
- [ ] Akamai 仅使用当前响应或匿名样本实际返回的完整签名 URL；其他已审核
      `bilivideo.com` 镜像可在严格内容等价验证后进行 host alias，不修改 path/query。
- [ ] `网络档案` 不同的主机健康状态互不命中；`auto` 只是共享档案，不声称自动
      识别 Wi-Fi、蜂窝或 SSID，需要隔离时手动使用不同档案名。
- [ ] 后台停留 30 分钟和 4 小时后恢复，首个视频仍立即起播；cron 尚未再运行、
      状态已过期或 Shadowrocket 回收脚本上下文时，热路径仍使用冷启动策略而不等待。
- [ ] `测速方式=off` 不发起后台或播放时 Range，但仍可复用未过期的已验证状态；
      `CDN=off` 完全不改写播放地址。
- [ ] `测速间隔=72` 的选择 TTL 不会被隐藏上限提前失效；更改 `CDN 学习状态`
      令牌只清空一次 v8 状态，再次使用相同令牌不重复清空。
- [ ] 固定主机只在目标完整 URL 已由当前同一媒体对象返回时提升；目标缺失、任一
      alias lane 缺失或签名不匹配时原样放行，可立即改回 `auto`/`off`。
