# BTR 分块下载移植与使用说明

版本：v3.15.0，2026-10-06。目标环境是官方 Bilibili iOS App + Shadowrocket，
无需额外设备或服务器。这是独立、默认关闭的实验模块；手机上的收益和稳定性仍需验收。

实现文件：`src/bilibili-btr.js`。改编依据是 Bilibili-thread-ripper
`bbf4d3dee502a16e424232ae6a51705f52b0e60d`，MIT 许可及版权保留在发行脚本内。
没有执行浏览器注入、MSE 接管或修改官方 App。

## 安装与配合

1. 保留一个当前 CDN-only 或 Enhanced 模块；不要同时启用两个基础变体。
2. 安装 [Bilibili.BTR.Experimental.sgmodule](https://raw.githubusercontent.com/STERILITZIA02/IOS_Bilibiliu_CDN_rewrite/main/dist/Bilibili.BTR.Experimental.sgmodule)。
3. 在该模块的编辑参数中设置 `启用加速=true`，重新应用配置。首次使用保持
   `并发数=auto`、`CDN模式=original`、`单次上限MiB=4`。
4. 完全退出 Bilibili 再打开，用固定视频和清晰度对照。需要诊断时临时开启调试日志。
5. 回滚时停用整个 BTR 模块并重新应用配置。参数开关只停止下载脚本；模块内的媒体
   MITM 主机列表仍存在。停用整个模块才撤销它额外加入的解密范围。

基础模块继续处理播放信息和广告/UI；BTR 只接管特定媒体 GET。两者不竞争相同 API
响应的写回权。无需把原基础模块换成 CDN-only，也无需关闭广告过滤。

## 已实现的能力

| 能力 | 实际行为 |
| --- | --- |
| 并发下载 | 将 App 本次有界 Range 分块，异步并发下载，按原偏移写回同一个输出缓冲 |
| 动态并发 | 自动档位 1、2、3、4、6、8；初始 2。按实际成功交付字节和整批耗时试探增加，增速不足 8% 回退并冷却；未验证的试探不持久保存 |
| 固定并发 | 支持 1–8，仍受并发上限控制 |
| 自适应块大小 | 64–512 KiB；同时参考传输结果和剩余范围，避免把含 RTT 的小包速度误当作持续带宽而产生几十次小请求 |
| 有限重试 | 已完成块保留；普通传输失败最多额外尝试一次，使用已验证备用路线或同一路线。没有可取消能力的超时不再发重试 |
| 多 CDN | 可选 mainland/overseas；最多两个维护候选通过各自的强版本条件、相同类型/总长和原地址首尾两处字节比对后才参与；各 CDN 使用自己的 If-Range 标签，不要求不同源的 ETag 相等 |
| 版本一致性 | 使用合法强 ETag；CDN 只返回未加引号标签时，使用满足 HTTP 强校验条件的 Last-Modified，并要求不透明标签一致 |
| 错误分类 | 429 以外的 4xx、版本或范围不符按地址 hash 短期退避；429 按网络和主机处理并参考 Retry-After；取消不惩罚节点；没有合格镜像时按当前签名和版本缓存两分钟，避免重复探测 |
| 资源管理 | 单次范围、并发、每次请求及总耗时均设限；协作租约限制同时接管的请求，每批重新检查所有权；失败不写回半份媒体 |
| 后台让路 | 真实媒体需求更新已有的节流活动时间戳，让基础模块后台测速暂停 |
| 隐私 | 持久化仅保留有上限的 hash、线程档位和时间；不保存完整媒体 URL、签名、Cookie、SSID 或正文；日志只输出结果与计数 |

“线程”在这里是并发 HTTP 请求数，不代表 JavaScript CPU 线程或独立 TCP 连接数。
HTTP/2 是否复用连接由网络引擎决定。动态并发基于下载结果，不冒充读取官方 App 的
缓冲余量、播放倍率或播放时钟。

## 参数

| 参数 | 默认 | 范围或说明 |
| --- | --- | --- |
| 启用加速 | false | 单独开启实验下载器 |
| 并发数 | auto | auto 或整数 1–8 |
| 并发上限 | 8 | 1–8，限制本次接管请求 |
| CDN模式 | original | original 仅原地址；mainland/overseas 启用维护候选的逐对象验证 |
| 单次上限MiB | 4 | 1–8；更大的 Range 原样交回 App |
| 执行预算毫秒 | 8000 | 2000–15000；模块脚本外层超时 20 秒 |
| 调试日志 | false | 输出 `[BiliBTR]` 的原因、耗时、实际峰值、并发变化和字节数 |

默认 original 可验证并发是否对当前线路有效。多 CDN 模式每次接管都需要校验候选，
会增加起始等待和流量；不能假设大陆或海外模式永远更快。first/last 采样和一致标签
提高同一性证据，但不构成整个远程文件的密码学证明。

## 协议与故障边界

- 只处理 HTTPS 下受支持 Bilibili 媒体主机的 `/upgcxcode/` `.m4s`/`.mp4`。
  不处理直播、API、页面和未知格式。Akamai 仅接受已审核的完整主机名。
- 只处理 `Range: bytes=start-end` 的单一闭合范围，最小 128 KiB，最大受参数控制。
  HEAD、开放/后缀/多范围、条件请求、携带 Cookie/Authorization 或未知请求头的
  请求、请求体、非标准端口均原样通过。初始化/索引的小请求不拆分。
- 每块必须是 206，起止与实长精确一致，完整文件总长度、媒体类型及版本条件不变。
  不接受压缩的媒体正文、重定向、文本形式二进制或错误页，不修改音视频时间戳、
  编码、清晰度、索引和播放器位置。
- Last-Modified 条件按 [RFC 9110 8.8.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.2.2)
  使用：响应 Date 至少晚 60 秒，日期格式有效；通过 If-Range 原样发送日期。
  不给非标准 ETag 擅自加引号。无足够版本条件时原样下载。
- 合成响应通过 `$done({ response: { status: 206, headers, body: Uint8Array } })`
  一次返回。Shadowrocket 二进制传输使用 `$httpClient` 的 binary-mode 和模块
  binary-body-mode；代码及 VM 契约测试已覆盖，真实 iOS 版本仍需确认。

## 无法等同于完整浏览器 BTR 的部分

1. **播放状态和 MSE。** Shadowrocket 无法访问另一个 App 的 video、SourceBuffer
   或音频时钟，因此没有移植按播放截止时间预取、主动清缓冲或直接修正音画位置。
2. **取消。** 若请求提供 signal、底层提供 abort/cancel，会主动取消。Shadowrocket
   当前适配接口未保证提供这些能力；没有句柄时只能停止排队、忽略迟到回调、用原生
   请求超时收尾并保留租约，不能宣称拖动后立刻终止全部底层下载。
3. **跨脚本全局并发。** persistentStore 不是已证实的原子锁。这里是写入后确认、
   每批核对的协作租约，冲突时原样通过；不能承诺整个 VPN 严格只有 N 条连接。
4. **流式输出和中途补尾。** App 要求的一个 Range 完整校验后才能回包。当前
   `$httpClient` 完成回调不提供已验证的中间字节进度，所以保留的是完整成功子块，
   不会捏造部分进度或承诺只补一个未完成块的尾部。无可靠取消时不启动重复慢块竞速。
5. **内存。** 本实现限制应用侧缓冲，但 `$httpClient` 如果遇到忽略 Range 的服务器，
   可能在回调前已缓冲过大正文。脚本不能保证提前制止这一行为，必须观察真实设备
   内存、VPN 稳定性与耗电后决定是否使用；默认关闭。

## 验证与实测

- `test/bilibili-btr.test.js` 覆盖真实异步并发、动态档位、乱序重组、版本变化、条件
  请求旁路、强日期校验、跨 CDN 排除、有限重试、限流/地址隔离、租约、取消、截止
  时间、背景测速让路和全新 Shadowrocket VM 的单次二进制完成。
- 本轮核心回归 273 项、站点回归 4 项通过；确定性构建、站点 lint 和生产构建通过。
- `npm run smoke:btr` 是可选真实网络检查；只访问匿名公开视频，下载同一个 2 MiB
  范围，对照原始下载和 BTR 重组的 SHA-256。可加 `-- --mode=mainland` 测试候选验证。
  脚本不输出完整签名 URL，流量有界，CI 不运行真实网络请求。
- 2026-10-06 本机海外线路、cosov 匿名样本：首版 64 KiB 小块产生 32 次请求，
  BTR 5208 ms，对照 1839 ms；据此调整块大小后变为 6 次请求，BTR 1851 ms，
  对照 1939 ms，实际峰值 2 路，重组字节完全一致。后一次差异很小，不能宣称
  普遍提速；“正确重组”“较少请求”“手机播放更流畅”是不同的验证结论。
- 同日 mainland 模式的另一次匿名样本未找到通过校验的大陆候选，保留原路线，
  5277 ms 对照 2028 ms，字节一致。候选验证有真实开销，因此默认 original；
  当前签名/版本验证失败后两分钟内不重复尝试镜像。不能把该模式标成已经实测更快。

发布前自动检查与实网结果不代替手机验收。需按相同视频/编码/网络对比基础模块与
基础模块+BTR，交替顺序测试连续播放、十次前跳/后退、倍速/清晰度切换、长暂停、
后台恢复和 Wi-Fi/蜂窝切换，记录首帧、缓冲总时长、花屏/音画偏移、流量、内存和耗电。
关闭整个 BTR 模块应立即恢复基础模块的媒体处理边界。
