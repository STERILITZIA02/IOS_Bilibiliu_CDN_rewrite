# v3.8.2 魔力赏残留审计

## 现象

启用 Enhanced 的 `广告过滤` 后，部分魔力赏推荐仍可能出现在首页、相关推荐，或在
视频暂停、拖动进度和从后台恢复后重新出现。

## 根因

确认存在两条独立载荷路径：

1. JSON 推荐卡仍声明为普通 `av`，只在 `badge`、`ad_tag`、`rcmd_reason` 等已审核
   营销元数据中写入“魔力赏”。原有商业词集合没有该标记，因此卡片通过普通视频
   白名单。
2. 播放页 gRPC 的进度/暂停操作卡会携带 Bilibili 商城的 `mall-magic-c` 路由。
   原有商业 URL 证据集合未包含该路由族，后台恢复后的新响应可以再次注入卡片。

## 修复

- 把简体和繁体“魔力赏/魔力賞”加入现有高置信营销元数据判据。
- 把 `mall-magic-c` 加入已审核 gRPC 商业 URL 证据，只在既有 ViewProgress、
  PlayPause 等精确方法和字段内使用。
- 保持请求侧缓存保护不变，因此暂停或后台恢复拿到的新响应仍会再次经过过滤。
- 不把 `mall.bilibili.com` 加入 MITM，也不阻断整个会员购/商城域名。

## 误伤边界

普通视频标题不属于商业元数据。标题为“魔力赏活动复盘”等用户内容仍保留；只有
角标、推荐理由、商业动作或已审核 gRPC 字段内的明确魔力赏路由会触发删除。账号、
会员、订单、支付、播放地址、普通进度点、互动卡和未知字段不在目标范围内。

## 自动验证

- 新增 JSON 回归：删除魔力赏推荐角标，同时保留标题含“魔力赏”的普通视频。
- 扩展 gRPC `ViewProgress` 回归：删除 `mall-magic-c` 操作卡并保留普通材料。
- 完整核心回归共 129 项；网站与确定性发行构建由 `npm run check:all` 统一验证。

真机最终确认仍应按 [iOS / Shadowrocket 真机验收清单](DEVICE_ACCEPTANCE.md) 执行。
