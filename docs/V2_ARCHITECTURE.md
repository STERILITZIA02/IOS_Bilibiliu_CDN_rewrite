# v2 安全架构

> 状态：已实施；本文同时作为后续回归审查基线。

## 组件边界

v2 拆分为两个独立脚本：

1. `bilibili-enhance.js`
   - 只处理体积受控的 Bilibili API JSON 响应。
   - 负责高置信广告过滤与可配置界面精简。
   - 任意异常都返回原始响应。
2. `bilibili-cdn.js`
   - 只处理播放地址 API 返回的 JSON/gRPC 元数据。
   - 不处理媒体分片响应体。
   - 自动模式只在同一个媒体对象内部提升已验证的服务端备用 URL。

两个脚本共享的只有构建约定和隐私规范，不共享响应缓存或对象状态。

## 广告与界面过滤

过滤器采用端点路由，不运行全局“猜测式递归删除”：

```text
请求 URL
  -> 精确端点分类
  -> 响应结构校验
  -> 多特征匹配
  -> 只删除目标数组元素/字段
  -> 保留未知结构
```

默认设置：

- `广告过滤=true`
- `界面精简=true`
- `搜索推广=true`
- `调试日志=false`

界面精简项可以按分类关闭。脚本不创建本地导航白名单，也不改变服务器返回顺序；删除后仅在字段明确存在时重新连续编号。

## CDN 安全自动模式

### 候选来源

一个媒体对象的候选集合仅由它自己的主 URL 和备用 URL 构成，并且不会在普通 CDN、MCDN 与 PCDN 家族之间提升候选。每个候选保留服务器返回的完整 scheme、host、path、query 和签名；自动模式不自行拼接签名 URL。

静态已知主机列表只供显式手动兼容模式选择，永不混入默认自动模式。

### 资源隔离

缓存键至少包含：

- 用户选择的网络档案；
- 内容资源路径的不可逆摘要；
- 音频/视频类型；
- 清晰度/表示 ID；
- 编码与带宽等可用表示字段；
- 候选集合摘要。

查询参数和完整 URL 不写入持久化状态或日志；缓存只保存固定长度摘要、计数和时间戳。不同资源、轨道、清晰度、编码或候选集合不能共享结果。

Shadowrocket 的公开脚本文档没有承诺可靠的 SSID/蜂窝标识变量，所以默认不会声称自动识别网络。用户可选网络档案用于明确隔离；默认档案使用较短 TTL，并在候选集合变化时立即失效。

### 验证

候选验证按以下顺序执行：

1. 使用 `GET` 发起 `bytes=0-16383` 小范围 `Range` 请求，不以 `HEAD` 成功代替媒体验证。
2. 只接受状态码 `206`、合法且从 0 开始的 `Content-Range`、媒体型 `Content-Type`、identity 编码和与范围一致的响应体大小。
3. HTML、文本/JSON 错误体、跳转到不同资源、压缩响应、范围或长度不一致、忽略 Range 的 `200` 响应均判为失败。

每次播放地址响应最多验证一个媒体对象的主 URL 与一条备用 URL；所有资源的探测全局至少间隔 2 分钟。未命中已验证缓存时返回原始响应；探测只用于后续同资源请求，避免将刚验证或未验证的 URL 直接交给播放器。

### 稳定性

- 新备用候选需要相隔至少 10 分钟的两次成功验证，并且速度优势达到阈值。
- 默认 `auto` 网络档案的选择 TTL 最长 6 小时；显式网络档案最长 24 小时。
- 已验证选择与候选集合绑定，持久化资源条目最多 64 个。
- 失败有计数和退避，不在每个请求上重测失败候选。
- 不修改已经发出的媒体请求，不在播放中途主动切换。
- 缓存损坏、测速超时、解析异常或存储失败时返回原始响应。

## 网络规则

- Bilibili API 与媒体域按配置规则分流。
- 可选 PCDN 阻断只匹配 `*pcdn*.biliapi.net`，模块默认策略为 `DIRECT`；用户可显式改为 `REJECT`。不添加宽泛 IP/CIDR。
- 统计/追踪只拦截经多来源核实且不会影响登录、支付、播放、弹幕或直播互动的独立端点。
- 默认不拦截 MCDN，不对媒体 CDN 域启用 MITM。

## 发布门槛

最终发行前必须完成：

- JSON 广告/UI fixture 测试与未知结构保留测试；
- JSON/gRPC 多轨、多清晰度候选隔离测试；
- Range 状态、Content-Range、Content-Type 和错误体测试；
- TTL、容量、锁、退避、滞后和失败回退测试；
- 构建可复现检查、模块语法检查和敏感信息扫描；
- Shadowrocket 手动验收清单与真实设备未验证项声明；
- 发行资产 SHA-256、GitHub Actions 状态和公开下载链接复核。
