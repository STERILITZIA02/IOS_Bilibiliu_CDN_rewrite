## 基线结果

当前 CDN 核心没有发现需要推倒重写的问题：

- `npm run check` 通过 44/44 项检查；
- `npm run smoke:auto` 从公开播放接口取得 6 个媒体描述；
- 本次网络冒烟中的两条服务端候选均通过严格 `GET Range` 校验并返回
  `206 Partial Content`；
- 广告/UI 和 CDN 已使用独立脚本，广告脚本不处理媒体分片正文；
- 自动 CDN 仍按资源、音视频轨、表示、编码、候选集合和网络档案隔离，
  并保留原始主地址与备用地址。

因此本轮不重写 `src/bilibili-cdn.js`，只扩充与双版本产物、文档和网站有关的
外围构建检查。

## 已确认缺口

1. `ViewUnite` 已能删除顶层 `cm`、游戏/广告关联卡、`cm_stock` 和
   `unique_id` 推广卡，但尚未覆盖当前上游确认的课程推广类型 `11`，以及
   详情区模块类型 `18`（活动横幅）、`29`（大会员横幅）和
   `55`（UP 主分享好物）。
2. 首页和“我的”页面只有一个总的 `界面精简` 开关，不能逐项保留或隐藏。
3. 旧的“我的”页匹配器在精确名称命中后允许任意非空 `id` 作为补充条件，
   范围偏宽；本轮改成每项独立的“稳定 ID / URI / 业务字段 + 精确名称”
   规则。
4. 模块尚未匹配大会员中心组合接口
   `/x/vip/web/vip_center/combine`，因此无法在不触碰 `user.vip`、钱包、
   订单或支付数据的前提下仅清空营销 `banners`。
5. 发行目录只有一个同时包含 CDN 和过滤脚本的模块，没有明确的
   “仅 CDN”与“CDN + 去广告/UI”两个版本。
6. 构建、校验和、Release 工作流和 README 都只认识单一模块产物。
7. 仓库没有可视化定制页，也没有能够根据固定白名单参数生成稳定订阅 URL
   的服务端入口。

## 安全边界

- 未知卡片、未知模块和无法解析的 JSON/Protobuf 原样保留；后续 `3.0.1`
  仅对已审核 Bilibili 方法的有界 gzip 帧增加了解压后精确过滤。
- 不按“纪录片”、标题、UP 主、封面文本或单一数字 ID 判断广告。
- 不改会员状态、到期时间、等级、B 币、硬币、订单、支付或账号安全数据。
- 不伪造会员、地区、运营商或网络请求头，不绕过充电视频、地区内容或付费
  内容的服务端授权；已合法取得的权益仍由 Bilibili 原始鉴权结果决定。
- 网站只接受固定参数白名单，只从本仓库固定 raw 路径获取模块，不接受用户
  提供的远程 URL，避免成为任意代理或脚本注入入口。
